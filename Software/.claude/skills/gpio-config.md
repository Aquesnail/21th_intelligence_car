# GPIO 引脚配置参考

本技能记录 STC32G12K128 GPIO 初始化完整配置，标注注释中的错误，用于查询引脚功能分配、电气模式及变更指导。

---

## STC32G GPIO 寄存器速查

| 寄存器 | 全称 | 功能 |
|--------|------|------|
| PxM1, PxM0 | Mode | 00=准双向, 01=推挽, 10=高阻输入, 11=开漏 |
| PxPU | Pull-Up | 1=使能内部上拉电阻 |
| PxIE | Input Enable | 1=使能数字输入, 0=关闭(用于模拟输入) |
| PxNCS | No CMOS Schmitt | 1=关闭施密特触发, 0=使能施密特(默认) |
| PxSR | Slew Rate | 1=慢摆率, 0=快摆率(高速信号) |
| PxDR | Drive | 1=增强驱动电流, 0=正常驱动 |
| PxIM0/1/2 | Interrupt Mode | 组合选择: 000=下降沿, 001=上升沿, 010=低电平, 011=高电平 |
| PxINTE | Interrupt Enable | 1=使能引脚外部中断 |
| PxBP | Bypass | 1=GPIO由用户控制, 0=可能被外设/ISP占用 |
| PINIPL/H | Priority Low/High | P0-P7中断优先级(00=最低, 11=最高) |
| PIN2IPL/H | Priority 2 Low/High | P8-PB中断优先级 |

## 初始化流程

### 1. GPIO_User_Control_On() — 强制所有端口进入用户控制

```c
P0BP-PBBP = 0xFF;  // 所有12个端口的Bypass寄存器置1
```

**作用**：释放所有引脚的控制权给用户手动配置，防止被 ISP/仿真/外设自动接管。在 `sys_init()` 中最早调用。

### 2. GPIO_Init() — 逐端口配置

**调用位置**：[main.c](Sources/User/main.c):45，在 `CLK_Init()` 之前。

## 逐端口详解

### P0 — ADC 模拟输入

```c
P0M1 = (PIN_0 | PIN_1 | PIN_2 | PIN_3 | PIN_4);  // P0.0-P0.4: M1=1, M0=0 → 高阻输入
P0M0 = 0x00;         // P0.5-P0.7: M1=0, M0=0 → 准双向
P0PU = 0x00;         // 全部无上拉
P0IE = ~0x1F;        // P0.0-P0.4: IE=0(关数字输入), P0.5-P0.7: IE=1(开)
P0NCS = 0x00;        // 全部使能施密特触发
```

| 引脚 | 模式 | 功能 | 数字输入 | 施密特 |
|------|------|------|----------|--------|
| P0.0-P0.4 | 高阻输入 | ADC | 关闭 ✓ | 使能 ⚠️ |
| P0.5-P0.7 | 准双向 | 未用 | 开 | 使能 |

**注释原文**：`P0.0-P0.4: ADC, 高阻输入; 其余浮空准双向` — **正确** ✓

**潜在问题** ⚠️：`P0NCS = 0x00` 使 ADC 引脚的施密特触发器保持使能状态。对于精密 ADC 采集，应将这些位的施密特触发器关闭（`P0NCS |= 0x1F`），以减少功耗和避免数字噪声耦合到模拟输入端。

### P1 — UART + 调试端口的混合配置

```c
P1M1 = PIN_2;                    // P1.2: M1=1 → 高阻
P1M0 = (PIN_7 | PIN_1 | PIN_6);  // P1.1, P1.6, P1.7: M0=1 → 推挽
P1PU = 0x00;                     // 全部无上拉
P1SR = ~PIN_1;                   // P1.1: 快摆率(TX), 其余: 慢摆率
P1DR &= ~PIN_1;                  // P1.1: 正常驱动电流
P1IE = ~(PIN_7 | PIN_6);         // P1.6, P1.7: 关数字输入; 其余: 开
P1INTE = 0x00;                   // 无外部中断
```

| 引脚 | 模式 (M1,M0) | 实际配置 | 注释声称 | 功能 |
|------|-------------|----------|----------|------|
| P1.0 | 00=准双向 | 准双向 | **准双向** ✓ | UART RX |
| P1.1 | 01=推挽 | 推挽 | **推挽** ✓ | UART TX |
| **P1.2** | **10=高阻输入** | **高阻输入** | "其余浮空准双向" ✗ | 未知 |
| P1.3-P1.5 | 00=准双向 | 准双向 | "其余" ✓ | 未用 |
| **P1.6** | **01=推挽** | **推挽** | **"保持原配置(高阻)" ✗** | 未知 |
| **P1.7** | **01=推挽** | **推挽** | **"保持原配置(高阻)" ✗** | 未知 |

**注释原文**：`P1.1: TX, 推挽;  P1.0: RX, 准双向;  P1.6, P1.7: 保持原配置(高阻); 其余浮空准双向`

**注释错误** ✗：
1. **P1.6, P1.7** — 注释说"保持原配置(高阻)"，但代码配置为**推挽**输出（`P1M0 |= PIN_7 | PIN_6`，且 `P1M1` 未置位）
2. **P1.2** — 注释说"其余浮空准双向"，但 P1.2 实际为**高阻输入**（`P1M1 = PIN_2`）
3. **"浮空"** — 代码 `P1PU = 0x00` 确实无上拉（浮空），但准双向口本身会有弱上拉特性，不算真正浮空

### P2 — SPI + 外部中断控制

```c
P2M1 = PIN_1 | PIN_0;            // P2.0, P2.1: M1=1 → 高阻
P2M0 = (PIN_2 | PIN_3 | PIN_5 | PIN_7); // P2.2, P2.3, P2.5, P2.7: M0=1 → 推挽
P2SR = ~(PIN_3 | PIN_5);         // P2.3, P2.5: 快摆率; 其余: 慢
P2DR &= ~(PIN_3 | PIN_5);        // P2.3, P2.5: 正常驱动
P2IM2 = PIN_0;                   // P2.0: 中断模式 [IM2=1,IM1=0,IM0=0] → 下降沿触发
SetP2IntPriority(2);             // P2中断优先级 → 2 (中等偏高)
P2IE = 0xFF;                     // 全部数字输入开
//P2INTE = PIN_0;                // ⚠️ 被注释掉 — P2.0外部中断实际上未使能！
```

| 引脚 | 模式 | 实际配置 | 注释声称 | 功能 |
|------|------|----------|----------|------|
| **P2.0** | **10=高阻输入** | **高阻输入** | **"准双向" ✗** | SPI_CTR_INT1 |
| **P2.1** | **10=高阻输入** | **高阻输入** | **"准双向" ✗** | SPI_CTR_INT2 |
| P2.2 | 01=推挽 | 推挽 | **推挽** ✓ | SPI_CTR_CS |
| P2.3 | 01=推挽 | 推挽 | **推挽** ✓ | SPI_MOSI |
| P2.4 | 00=准双向 | 准双向 | **准双向** ✓ | SPI_MISO |
| P2.5 | 01=推挽 | 推挽 | **推挽** ✓ | SPI_SCK |
| P2.6 | 00=准双向 | 准双向 | "其余" ✓ | 未用 |
| **P2.7** | **01=推挽** | **推挽** | **未提及 ✗** | 未知 |

**注释原文**：`P2.3: SPI_MOSI, P2.5: SPI_SCK, P2.2: SPI_CTR_CS — 推挽; P2.0: SPI_CTR_INT1, P2.1: SPI_CTR_INT2, P2.4: SPI_MISO — 准双向; 其余浮空准双向`

**注释错误** ✗：
1. **P2.0, P2.1** — 注释说"准双向"，实际为**高阻输入**。作为外部中断输入引脚（INT1/INT2），高阻输入是合理的选择，但注释未更新
2. **P2.7** — 配置为**推挽**输出，但注释完全未提及此引脚的功能用途

**配置矛盾** ⚠️：
- `P2IM2 = PIN_0` 和 `SetP2IntPriority(2)` 为 P2.0 配置了中断模式和优先级
- 但 `P2INTE` 被注释掉，意味着 P2.0 的**外部中断未使能**
- 如果 P2.0 需要产生中断，需要取消注释 `P2INTE = PIN_0` 或在别处使能

### P3 — ICM20602 SPI 接口

```c
P3M1 = 0x00;
P3M0 = (PIN_2 | PIN_4 | PIN_5);  // P3.2, P3.4, P3.5: 推挽
P3SR = ~(PIN_2 | PIN_4);         // P3.2, P3.4: 快摆率(SCK,MOSI); P3.5(CS): 慢
//P3DR &= ~(PIN_2 | PIN_4);      // 被注释 — 保持默认驱动能力
P3IE = 0xFF;                     // 全部数字输入开
```

| 引脚 | 模式 | 功能 | 注释正确性 |
|------|------|------|-----------|
| P3.0-P3.1 | 准双向 | 未用 | ✓ |
| P3.2 | 推挽 | ICM_SCK | ✓ |
| P3.3 | 准双向 | ICM_MISO | ✓ |
| P3.4 | 推挽 | ICM_MOSI | ✓ |
| P3.5 | 推挽 | ICM_CS | ✓ |
| P3.6-P3.7 | 准双向 | 未用 | ✓ |

**注释原文**：`P3.2: ICM_SCK, P3.4: ICM_MOSI, P3.5: ICM_CS — 推挽; P3.3: ICM_MISO — 准双向; 其余浮空准双向` — **正确** ✓

### P4 — 全准双向 + 中断输入

```c
P4M1 = 0x00; P4M0 = 0x00;   // 所有准双向
P4PU = 0x00;                 // 无上拉
P4IE = 0xFF;                 // 全部数字输入开
P4INTE = 0x00;               // 无外部中断使能
```

| 引脚 | 模式 | 功能 | 备注 |
|------|------|------|------|
| P4.0-P4.7 | 准双向 | 未用 | 全浮空 |

**注释原文**：`全浮空准双向` — **正确** ✓

**备注**：虽然 RTOS 中注册了 `P4_ISR_Handle`（`configUSE_RTOS_P4 = 1`），但 `P4INTE = 0x00` 表示初始化时未使能任何引脚的硬件外部中断。P4 中断可能在运行时由其他外设触发，或由外部单独使能。

### P5 — ICM20602 中断 + 额外触发源

```c
P5M1 = 0x00;
P5M0 = PIN_0;                    // P5.0: 推挽
P5PU = PIN_1;                    // P5.1: 上拉
//P5SR = ~(PIN_4);               // 被注释 — 原因不明
P5IE = 0xFF;                     // 全部数字输入开
P5IM2 &= ~(PIN_1 | PIN_4);       // P5.1, P5.4: IM2=0
P5IM1 &= ~(PIN_1 | PIN_4);       // P5.1, P5.4: IM1=0
P5IM0 &= ~(PIN_1 | PIN_4);       // P5.1, P5.4: IM0=0
                                  // → P5.1, P5.4: 下降沿触发
P5INTE = PIN_1 | PIN_4;          // P5.1, P5.4: 外部中断使能
```

| 引脚 | 模式 | 上拉 | 中断 | 注释声称 | 实际功能 |
|------|------|------|------|----------|----------|
| P5.0 | 推挽 | 无 | 无 | ICM_INT2 | ICM_INT2(?) 推挽输出 |
| P5.1 | 准双向 | 有 | 下降沿 | ICM_INT1 | ICM_INT1 下降沿中断输入 |
| **P5.4** | 准双向 | 无 | **下降沿** | **未提及 ✗** | 未知来源下降沿中断输入 |
| P5.2-P5.3, P5.5-P5.7 | 准双向 | 无 | 无 | "其余" | 未用 |

**注释原文**：`P5.0: ICM_INT2, 推挽; P5.1: ICM_INT1, 准双向, 上拉开, 中断开(下降沿); 其余浮空准双向`

**注释遗漏** ✗：
1. **P5.4** — 注释完全未提及，但代码为 P5.4 配置了与 P5.1 相同的下降沿中断（`P5INTE = PIN_1 | PIN_4`），这个引脚也作为外部中断源使用
2. **P5SR 注释行** — `P5SR = ~(PIN_4)` 被注释掉，如果 P5.4 需要高速信号响应，可能需要取消注释

**命名疑问** ⚠️：
- 注释说 P5.0 是"ICM_INT2"（推挽输出），P5.1 是"ICM_INT1"（准双向输入）
- 通常 ICM20602 的 INT1/INT2 都是**输入**引脚（传感器中断输出→MCU输入），P5.0 配置为推挽输出与"INT"的语义矛盾
- 可能 P5.0 的实际功能不是 ICM_INT2，或是需要输出信号给 ICM

## 中断优先级全局配置

```c
PINIPL = 0x00; PINIPH = 0x00;    // P0-P7: 中断优先级 → 00 (最低)
PIN2IPL = 0x00; PIN2IPH = 0x00;  // P8-PB: 中断优先级 → 00 (最低)
```

所有端口中断初始化为最低优先级 0。P2 的优先级在端口配置中被单独设为 2（`SetP2IntPriority(2)`），这个调用会覆盖 P2 在 `PINIPL/H` 中的对应位。

## 配置问题与待确认项

1. **P0NCS = 0x00**：ADC 引脚（P0.0-P0.4）未关闭施密特触发器。如 ADC 精度有问题，考虑 `P0NCS |= 0x1F`
2. **P2INTE 被注释**：P2.0 中断模式/优先级已配置但中断未使能。需确认：是忘记取消注释，还是改为运行时使能？
3. **P5.0 功能存疑**：注释称 ICM_INT2 但配置为推挽输出，与"INT"语义矛盾
4. **P5SR 被注释**：`P5SR = ~(PIN_4)` — 如果 P5.4 是中断信号，快摆率可能不需要，但要确认
5. **P3DR 被注释**：`P3DR &= ~(PIN_2 | PIN_4)` — SPI 引脚使用默认驱动能力，如通信有干扰可取消注释降低驱动
6. **P1.2 高阻输入**：功能未被文档化，可能是预留的模拟输入或特殊用途
