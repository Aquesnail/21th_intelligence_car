# 盲盒停车任务模块

## 概述

智能车竞赛"盲盒任务"——在**第 N 次经过某个赛道元素**时精准停车。例如："第3次进入 WALL 时停下"。

本模块在现有元素状态机和刹车系统之上新增一层"何时刹车"的决策逻辑，完全复用已有的 `ELEMENT_BRAKING → ELEMENT_SAFETY_STOP` 刹车链路，不新增任何制动方式。

---

## 快速上手

### 一条命令配置

通过上位机串口终端发送文本命令（协议帧 `CMD_TEXT = 0x57`）：

```
bbtask 3 4        第3次进入元素类型 4 (=ELEMENT_CROSS) 时停车
bbtask 2 6        第2次进入元素类型 6 (=ELEMENT_SKIP) 时停车
bbtask 1 3 0.15   第1次进入 WALL，进入后延迟 0.15(米) 再停
bbtask off        关闭盲盒任务，正常跑
bbtask status     回显当前配置
```

### 元素类型编号对照

使用 `element_t` 枚举值（见 [element.h](Sources/User/element.h)）：

| 值 | 枚举名 | 含义 |
|----|--------|------|
| 0 | `ELEMENT_STRAIGHT` | 直道（不可用于盲盒） |
| 1 | `ELEMENT_RING_LEFT_ENTRANCE` | 左环岛入口 |
| 2 | `ELEMENT_RING_RIGHT_ENTRANCE` | 右环岛入口 |
| 3 | `ELEMENT_WALL` | 上墙 |
| 4 | `ELEMENT_CROSS` | 十字 |
| 5 | `ELEMENT_BARREL` | 滚筒 |
| 6 | `ELEMENT_SKIP` | 跷跷板 |
| ... | （子状态） | 一般不直接作为盲盒目标 |

**常用目标**是顶层入口元素（3~6），即 WALL / CROSS / BARREL / SKIP。子状态如 WALL_CLIMB、BARREL_DESCEND 等也可用，但触发点更靠后。

│                                                    │
│  ① 安全检测层 (off-track / timeout)                 │
│  ② BRAKING / SAFETY_STOP 状态维护                   │
│  ③ 投票窗更新 + 状态转移评估                          │
│  ④ ★ 盲盒检查 (新增)                                │
│     ├─ 条件: enable && 刚进入非STRAIGHT元素           │
│     ├─ 匹配: 当前元素 == BB_TgtElem                   │
│     │        出现次数++ == BB_TgtOcc → 触发           │
│     └─ 动作: 写 braking_frame_cnt, 切 ELEMENT_BRAKING │

│  现有刹车链路 (完全复用)                             │
│                                                    │

│    → 风扇保持运转                                    │
│    ↓ 200帧后                                        │
│  ELEMENT_SAFETY_STOP (CTRL_BRAKE)                   │

## 出现次数计数机制

不依赖圈数，直接统计目标元素被进入的次数：

```
Element_Update() 每帧执行:

    Element_EvaluateTransitions() → STRAIGHT → WALL 转移完成
        │  ctx->prev    = ELEMENT_STRAIGHT
        │  ctx->current = ELEMENT_WALL
        │
        ▼
    盲盒检查:
        ctx->current == BB_TgtElem(=WALL) ?
            ├─ YES → blindbox_occurrence_cnt++
            │
            └─ blindbox_occurrence_cnt == BB_TgtOcc ?
                   ├─ YES → 触发刹车
                   └─ NO  → 继续行驶, 等待下次出现
```

- 计数器 `blindbox_occurrence_cnt` 在**每次进入**目标元素时 +1
- 只有当 `blindbox_occurrence_cnt == BB_TgtOcc` 时才触发
- 不是目标元素的其他元素完全不影响计数
- 系统复位时计数器归零

### 示例：`bbtask 3 3`（第3次 WALL 停车）

```
经历顺序:
  SKIP → BARREL → RING → WALL     occurrence_cnt=1 (不触发, 目标=3)
  SKIP → BARREL → RING → WALL     occurrence_cnt=2 (不触发)
  SKIP → BARREL → RING → WALL     occurrence_cnt=3 → ★ 触发刹车!
```

## 两种停车模式

### 模式 0：进入即停（默认）

`BB_StopMode = 0`

```
STRAIGHT → 目标元素 (状态转移)
    │
    └─ 同一帧内检测到出现次数达标
       → ctx->current = ELEMENT_BRAKING
       → braking_frame_cnt = 200
       → 0.4s 刹车力矩 → SAFETY_STOP
```

### 模式 1：延迟距离停

`BB_StopMode = 1`, `BB_Delay = 0.15`（示例值）

```
STRAIGHT → 目标元素 (状态转移)
    │
    ├─ 同一帧: 记录 blindbox_dist_start = g_total_distance
    ├─ 每帧:   检测 (g_total_distance - 快照) >= BB_Delay ?
    │          YES → 触发 ELEMENT_BRAKING
    │          NO  → 继续行驶
    │
    └─ 安全兜底: 若未达到距离就退出了元素 → 清除盲盒状态, 不触发
```

**标定方法**：手推车走一遍目标元素，观察上位机 `TotalDist` 增量，设置合适的 `BB_Delay`。

**注意**：`g_total_distance` 来自电机编码器实际转速积分，轮胎打滑空转时里程会偏大。

## 上位机配置方式

### 方式一：文本命令（推荐）

| 命令 | 效果 |
|------|------|
| `bbtask 3 4` | 第3次进入 CROSS(4) 时停车 |
| `bbtask 2 6` | 第2次进入 SKIP(6) 时停车 |
| `bbtask 1 3 0.15` | 第1次进入 WALL(3)，进入后延迟 0.15 再停 |
| `bbtask off` | 关闭盲盒 |
| `bbtask status` | 回显当前配置 |

发送任意串口终端即可，协议帧类型为 `CMD_TEXT (0x57)`。

### 方式二：上位机 GUI 变量读写

变量按 `VAR_CAT_ELEMENT / VAR_ELEM_GLOBAL` 注册，在上位机"元素"面板可见：

| 变量名 | 类型 | 说明 |
|--------|------|------|
| `BB_Enable` | uint8 | 0=关闭, 1=开启 |
| `BB_TgtOcc` | uint8 | 第几次出现时停车 (1-based) |
| `BB_TgtElem` | uint8 | 目标元素类型 (element_t 枚举值) |
| `BB_StopMode` | uint8 | 0=立即停, 1=延迟停 |
| `BB_Delay` | float | 延迟距离阈值 |
| `BB_OccCnt` | uint8 | 只读，目标元素已出现次数（高频上传） |
| `BB_TblWrap` | uint8 | 赛道表回绕开关 |

## 刹车参数微调

盲盒停车复用同一套刹车参数，无需额外调整：

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `El_BrkFrames` | 200 | 刹车力矩持续帧数 (500Hz, 200帧=0.4s) |
| `El_BrkSpeed` | 0.1 | 刹车目标速度 (rad/s)，增大=更强刹车力矩 |

## 赛道表更换

更换赛道只需修改 `element.c` 中两处：

```c
#define TRACK_TABLE_LEN  6   // ← 改长度

static const unsigned char g_track_table[TRACK_TABLE_LEN] = {
    ELEMENT_SKIP,             // ← 索引 0
    ELEMENT_CROSS,            // ← 索引 1
    ELEMENT_WALL,             // ← 索引 2
    ELEMENT_BARREL,           // ← 索引 3
    ELEMENT_RING_LEFT_ENTRANCE, // ← 索引 4
    ELEMENT_CROSS,            // ← 索引 5
};
```

赛道表只影响投票窗预期（防止环岛方向误判），**不影响盲盒触发**。盲盒只看元素类型 `BB_TgtElem`，不依赖赛道表内容。

## 状态机流程图

```
上电
 │  blindbox_occurrence_cnt = 0
 │
 ├─ 手动模式
 │    │  发送 "bbtask 3 3" → 第3次 WALL 停车
 │    │  → BB_Enable=1, BB_TgtOcc=3, BB_TgtElem=3
 │    │
 │    └─ 切自动模式
 │
 ├─ 自动模式 — 正常运行
 │    │
 │    ├─ SKIP → BARREL → RING → WALL (第1次)
 │    │   │  occurrence_cnt = 1, 不触发 (目标=3)
 │    │   │
 │    ├─ SKIP → BARREL → RING → WALL (第2次)
 │    │   │  occurrence_cnt = 2, 不触发
 │    │   │
 │    ├─ SKIP → BARREL → RING → WALL (第3次)
 │    │   │  occurrence_cnt = 3 == BB_TgtOcc !
 │    │   │
 │    │   └─ STRAIGHT → WALL 转移完成
 │    │      ctx->prev    == STRAIGHT  ✔
 │    │      ctx->current == WALL      ✔
 │    │      occurrence_cnt == 3       ✔
 │    │      → 触发 ELEMENT_BRAKING !
 │    │
 │    ├─ BRAKING: 200帧刹车力矩
 │    │
 │    └─ SAFETY_STOP: 电机断电, 风扇关闭
 │       → 任一 ADC 恢复 → System_Reset() → 手动模式
 │       → 人工取车, 任务完成
```

## 边界与安全

| 场景 | 行为 |
|------|------|
| `BB_Enable=0` | 盲盒检查完全跳过，不影响正常行驶 |
| 目标元素从未出现 | `occurrence_cnt` 不增长，不触发 |
| STRAIGHT 作为目标 (elem=0) | 刚进入 STRAIGHT 时 `prev==STRAIGHT` 不满足，不触发 |
| 模式1下未达距离就退出元素 | `ctx->current == STRAIGHT` 时清除 blindbox_active |
| BRAKING/SAFETY_STOP 期间 | `ctx->current != BRAKING/SAFETY_STOP` 条件拦截 |
| 系统复位 | `Element_ResetTrackIndex` 清零 occurrence_cnt 和 blindbox_active |
| 单元素调试 (`track_table_enabled=0`) | 正常工作，盲盒只看元素类型不看赛道表 |
